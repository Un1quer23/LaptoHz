# 手动模式交互调整方案

日期：2026-10-04。方案已在 v0.2.5 实现。v0.3.0-beta.1 将固定两档扩展为动态有效档位，增加插电／电池目标子菜单，保留先进入手动模式的操作；当前行为见 [使用说明](../README.md)，当前测试见 [验证记录](../VALIDATION.md)。以下保留基于 v0.2.4 的研究过程与截图。

## 结论

采用明确的两步操作：先选择手动模式，再选择目标刷新率。当前档位保留显示并置灰；自动和确认模式下，两个手动档位都置灰，并显示“请先选择手动模式”。进入手动模式只改变模式，不改变当前刷新率。为保持操作连贯，选择手动模式后在同一位置继续显示更新后的菜单。

这项调整替代旧约定“点任一档位自动进入手动模式、当前档位也可选”。保留左右键统一菜单、深浅色、模式记忆、自启、确认窗和显示校验。

## 现状检查与截图

本次用现有 CreateTrayMenu / TrayMenuRenderer 及原生菜单消息捕获三个状态，未改变用户实际模式、刷新率、自启或 Windows 主题。截图来自隔离窗口，供电和档位由测试快照提供；档位选择只返回命令编号，未调用真实显示切换。

3. **选择另一档：当前文字更新，重复操作仍然开放。** 手动 60Hz 时，60Hz 项仍可选。当前实现会再次保存手动模式并提交无须改变显示的请求，再弹出“当前已是”结果提示。

截图支持菜单排序、标签和可用状态的判断；源码支持模式与请求处理的判断。隔离试验验证了选中模式后可在同一锚点重新展示菜单并继续选择档位，尚未验证接入完整 App 后的鼠标、焦点、右键重复通知和锁屏行为。未据此声称完成辅助技术或实机切换验收。

## 推荐交互

菜单顺序：当前状态 → 自动 / 确认 / 手动模式 → 手动刷新率 → 自启 / 日志 / 退出。三种模式继续使用互斥圆点；刷新率项不用圆点或勾。

刷新率保持两个固定位置。标签统一用“60Hz”“240Hz”，当前档位追加“（当前）”；分组标题“手动刷新率”说明动作含义。非手动模式在该组增加常显说明“请先选择手动模式”，避免用户把置灰理解为屏幕故障。说明文字使用可读的次级文字色，不与不可用按钮一同降低辨识度，也不依赖悬停提示。

| 模式与实际档位 | 60Hz | 240Hz | 说明 |
|---|---|---|---|
| 自动 / 确认 | 置灰 | 置灰 | 请先选择手动模式；实际档位仍标“（当前）” |
| 手动、当前 240Hz | 可选 | 置灰、标当前 | 点击 60Hz 直接切换 |
| 手动、当前 60Hz | 置灰、标当前 | 可选 | 点击 240Hz 直接切换 |
| 手动、当前为其他档位 | 按支持情况可选 | 按支持情况可选 | 顶部保留实际刷新率，不把它误认成 60 / 240Hz |
| 正在切换 / 状态未知 / 会话不可用 | 置灰 | 置灰 | 显示正在切换或不可用原因 |

从自动或确认切入手动：保存模式，取消未执行的自动任务及旧确认建议，保持当前刷新率；刷新并继续显示同一位置的菜单。此时菜单和顶部模式已提供反馈，无需再出现成功进入手动模式的结果弹窗；保存失败仍明确提示，当前运行继续采用手动模式。

手动选择另一档：执行后关闭菜单，成功显示现有五秒结果提示；失败保持手动模式，说明原因。当前档位的点击、Enter 和旧命令均不执行切换，也不弹出多余的“已是当前”提示。菜单关闭、锁屏或程序退出后不得被迟到的继续显示请求重新打开。

恢复自动模式仍立即按供电核对；进入确认模式仍只建立供电基线。确认窗的“切换”属于确认流程，在确认模式下继续可用，不受手动菜单档位的限制。

## 实现范围

- **菜单层：** 调整分组顺序和标签；目标启用条件为手动模式、会话可用、未忙且 CheckTarget 返回 apply。现有 unchanged 判断已能识别当前档位，可复用实际刷新率匹配规则。
- **控制器层：** 分离进入手动模式与执行手动刷新率。ManualSwitch 不再隐式调用 SetMode；执行入口重新检查模式、忙闲和当前显示状态。后台线程也要求请求属于当前手动模式，继续检查请求编号、输出路径和取消状态。
- **连续操作：** 当前 TrackPopupMenuEx 使用 TPM_RETURNCMD，选中后返回，再执行模式变更。建议在同一个菜单会话内按原锚点再展示更新后的菜单，避免递归打开；保留重复托盘通知保护，并对关闭、锁屏和退出做专门回归。
- **命令参数：** 建议 --switch 60 / 240 同样要求已进入手动模式；非手动状态明确拒绝并提示先用 --mode manual，不能只禁用菜单而保留隐式模式变更。现有命令使用 PostMessage，只能报告已投递；若要返回拒绝原因，应增加有超时的请求应答，区分请求接受与切换最终完成。--pause / --resume 仍映射手动 / 自动。
- **竞态处理：** 选择后重新读到目标已是当前时，只刷新菜单和状态，不重新应用或弹成功提示。进入手动模式可撤销未执行的任务；已进入驱动调用的切换不能保证瞬间撤回，须回读实际结果并丢弃旧界面反馈。
- **边界保留：** DRR、复制、远程会话、缺失档位和内屏不可用仍按原规则限制，不因进入手动而绕过校验。

## 验收重点

1. 自动与确认下，鼠标、键盘和直接命令均不能隐式进入手动并切档；确认窗执行不受影响。
2. 进入手动保留当前刷新率、模式可持久化；菜单继续显示并明确标记手动，关闭后不会自行重开。
3. 当前档位置灰且不能提交；另一档可执行。实际为 120Hz 等其他档位时不误标当前 60 / 240Hz。
4. 切换成功、失败、状态变更、读回已是当前、快速连续点击均无重复提交或多余提示；主题与高对比度下置灰及说明仍可辨识。
5. 连续右键通知、点击外部、Esc、锁屏、显示器与 DPI 定位、睡眠恢复、保存失败和旧请求处理保持正确。

## 依据

- [Microsoft：Win32 菜单的启用、置灰和禁用](https://learn.microsoft.com/en-us/windows/win32/menurc/about-menus#enabled-grayed-and-disabled-menu-items)：置灰是不可执行动作的视觉提示，并阻止选择。
- [Microsoft：原生菜单设计原则](https://learn.microsoft.com/en-us/windows/win32/uxguide/cmd-menus)：相关选项成组、逻辑顺序优先，成对项目可保留并禁用；模式用圆点，动作不用选择标记。这份指南以 Windows 7 为背景，仅引用仍适用的菜单组织原则。
- [Microsoft：TrackPopupMenuEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-trackpopupmenuex)：TPM_RETURNCMD 返回所选命令；继续显示菜单需要程序处理，不能仅更新启用状态就假定原生菜单保持打开。
